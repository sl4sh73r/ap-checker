## 🎯 Введение

Эта лабораторная работа научит вас работать с документацией в GitHub. Вы узнаете, как:
- Создавать и структурировать Wiki-страницы
- Использовать Markdown для форматирования текста
- Работать с Git для версионирования документации
- Организовывать навигацию по документам

GitHub предлагает два основных способа документирования:
1. **GitHub Wiki** — отдельное пространство для документации
2. **Папка `docs/`** — документация внутри репозитория (используется в этом проекте)

## 📂 Шаг 1: Подготовка Wiki/Docs

### Вариант A: Использование GitHub Wiki

GitHub Wiki доступна в репозитории через вкладку "Wiki". 

**Создание Wiki:**
1. Перейдите на страницу вашего репозитория на GitHub
2. Нажмите на вкладку **Wiki**
3. Нажмите **Create the first page**
4. Создайте главную страницу с названием **"Домашняя"** или **"Home"**

**Клонирование Wiki локально:**
```bash
# Wiki — это отдельный Git-репозиторий
git clone https://github.com/username/repository.wiki.git
cd repository.wiki
```

### Вариант B: Использование папки `docs/` (рекомендуется)

Создайте папку `docs` в корне проекта для хранения документации:

```bash
# Создаём папку docs
mkdir docs

# Создаём главную страницу
touch docs/README.md
# или
touch docs/Домашняя.md
```

**Содержимое главной страницы `docs/README.md`:**
```markdown
# Домашняя страница

Добро пожаловать в документацию проекта!

## О проекте

Здесь вы найдете всю необходимую информацию для работы с проектом.

## Разделы документации

- [Начало работы](Начало-работы.md)
- [Окружение для разработки](Окружение-для-разработки.md)
- [Предстоящие события](Предстоящие-события/)
```

**Зафиксируйте изменения:**
```bash
git add docs/
git commit -m "Добавлена главная страница документации"
git push origin main
```

💡 **Подсказка:** На GitHub можно настроить GitHub Pages для автоматической публикации документации из папки `docs/`.

## 🔄 Шаг 3: Внесение изменений и коммиты

Практика работы с Git — важная часть управления документацией.

### Редактирование существующих страниц

1. **Откройте файл для редактирования:**
   ```bash
   code docs/Начало-работы.md
   ```

2. **Внесите изменения** (например, добавьте новый раздел)

3. **Проверьте статус репозитория:**
   ```bash
   git status
   ```

4. **Просмотрите изменения:**
   ```bash
   git diff docs/Начало-работы.md
   ```

5. **Зафиксируйте изменения:**
   ```bash
   git add docs/Начало-работы.md
   git commit -m "Обновлена страница 'Начало работы': добавлен раздел о настройке"
   git push origin main
   ```

### Примеры хороших commit-сообщений

✅ **Хорошие примеры:**
- `Добавлена страница о системных требованиях`
- `Исправлены опечатки в документации`
- `Обновлены ссылки на внешние ресурсы`
- `Добавлен раздел о настройке окружения`

❌ **Плохие примеры:**
- `Update` (слишком общее)
- `Fix` (непонятно, что исправлено)
- `asdfgh` (бессмысленное)

### Просмотр истории изменений

```bash
# Посмотреть историю коммитов
git log --oneline

# Посмотреть изменения в конкретном файле
git log -p docs/Начало-работы.md

# Посмотреть, кто и когда менял строки в файле
git blame docs/Начало-работы.md
```

💡 **Подсказка:** На GitHub вы можете увидеть историю изменений файла, нажав кнопку "History" в правом верхнем углу при просмотре файла.

## 🔍 Шаг 6: Проверка работы Wiki

### Проверка навигации

1. **На GitHub:**
   - Перейдите в папку `docs/` вашего репозитория
   - Убедитесь, что все ссылки между страницами работают
   - Проверьте, что Markdown правильно отображается

2. **Локально:**
   - Откройте файлы `.md` в VS Code с расширением Markdown Preview
   - Проверьте корректность ссылок и форматирования

### Проверка поиска

#### На GitHub:
- Используйте поиск репозитория (нажмите `/` или кликните на строку поиска)
- Введите ключевые слова из документации
- GitHub автоматически индексирует содержимое `.md` файлов

#### С помощью grep (локально):
```bash
# Поиск по всем файлам документации
grep -r "искомая фраза" docs/

# Поиск с номерами строк
grep -rn "искомая фраза" docs/

# Поиск без учёта регистра
grep -ri "искомая фраза" docs/
```

### Проверка истории изменений

```bash
# Просмотр истории всей документации
git log --oneline -- docs/

# Просмотр изменений конкретного файла
git log -p docs/Начало-работы.md

# Просмотр изменений за последнюю неделю
git log --since="1 week ago" -- docs/
```

### Тестирование ссылок

```bash
# Установите markdown-link-check (опционально)
npm install -g markdown-link-check

# Проверьте ссылки в документации
find docs/ -name "*.md" -exec markdown-link-check {} \;
```

## 📖 Как работать с документацией

### Где писать документацию?

- **Техническая документация** → `docs/`
- **Описание проекта** → `README.md` (корень репозитория)
- **Комментарии к коду** → непосредственно в исходных файлах
- **Changelog** → `CHANGELOG.md` (если необходим)

### Как добавить новую страницу?

1. **Создайте новый файл** в папке `docs/`:
   ```bash
   touch docs/Новая-страница.md
   ```

2. **Добавьте содержимое** в формате Markdown:
   ```markdown
   # Заголовок страницы
   
   Содержимое страницы...
   ```

3. **Добавьте ссылку** на новую страницу в `docs/README.md`:
   ```markdown
   - [Новая страница](Новая-страница.md)
   ```

4. **Зафиксируйте изменения**:
   ```bash
   git add docs/
   git commit -m "Добавлена новая страница документации"
   git push origin main
   ```

### Как редактировать существующую страницу?

1. **Откройте файл** для редактирования:
   ```bash
   code docs/Начало-работы.md
   # или используйте любой текстовый редактор
   ```

2. **Внесите изменения** и сохраните файл

3. **Проверьте изменения**:
   ```bash
   git diff docs/Начало-работы.md
   ```

4. **Зафиксируйте изменения**:
   ```bash
   git add docs/Начало-работы.md
   git commit -m "Обновлена страница: добавлен раздел X"
   git push origin main
   ```

### Как посмотреть историю изменений?

#### На GitHub:
1. Откройте нужный файл в репозитории
2. Нажмите кнопку **History** (в правом верхнем углу)
3. Просмотрите список коммитов, изменявших этот файл
4. Кликните на коммит, чтобы увидеть детали изменений

#### Локально через Git:
```bash
# История изменений файла
git log docs/Начало-работы.md

# Подробная история с содержимым изменений
git log -p docs/Начало-работы.md

# Краткая история (одна строка на коммит)
git log --oneline docs/Начало-работы.md

# Кто и когда изменял каждую строку
git blame docs/Начало-работы.md
```
